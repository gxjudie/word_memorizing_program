# 文脈で覚える · 일본어 문맥 단어장

새로운 일본어 예문과 간격 반복으로 단어를 문맥 속에서 익히는 웹 애플리케이션입니다. React + TypeScript SPA와 FastAPI 백엔드로 구성되어 있습니다.

## 주요 기능

- 일본어 단어, 읽기, 뜻을 직접 추가
- 기존 Anki 덱(.apkg 또는 텍스트 .txt/.tsv)을 미리보기로 확인한 뒤 한 번에 가져오기
- 오늘 복습할 단어를 한 번에 하나씩 제시
- 매 복습마다 목표 단어가 포함된 새 예문 생성 (Google Gemini API)
- 문장 속 단어의 읽기와 뜻 확인
- 4단계 자기 평가와 간격 반복 일정 계산
- "Google로 계속하기" 로그인 (본인 확인 전용)
- 사용자 본인의 무료 Gemini API 키 연결 (앱 안의 단계별 안내 포함)

## 인증과 AI 사용 방식

- **로그인**: Google OAuth 2.0 Authorization Code + PKCE + OpenID Connect를 사용하며, `openid email profile` 범위만 요청합니다. Google 계정은 본인 확인에만 쓰입니다. Google 액세스 토큰과 갱신 토큰은 로그인 직후 버려지고 저장되지 않습니다. 브라우저에는 백엔드가 발급한 앱 전용 세션만 저장됩니다.
- **예문 생성**: 각 사용자가 Google AI Studio에서 직접 만든 Gemini API 키를 앱에 붙여넣습니다. 백엔드는 키를 한 번 검증한 뒤 사용자별로 암호화(Fernet)해서 저장하고, 브라우저에는 마지막 4자리만 보여 줍니다. 개발자 소유의 Gemini 키는 없습니다.
- 키가 없어도 로그인과 단어 추가는 할 수 있습니다. 복습(예문 생성)을 시작할 때 키 연결 안내가 표시됩니다.

## 사전 준비

- Python 3.11 이상
- Node.js 18 이상과 npm
- Google 계정 (Google Cloud Console에서 OAuth 클라이언트를 만들 때 사용)

로컬 기본값은 SQLite를 사용하므로 별도 데이터베이스 서버가 필요하지 않습니다.

## 1. Google OAuth 클라이언트 만들기 (개발자용, 한 번만)

로그인에 쓸 OAuth 클라이언트를 Google Cloud Console에서 만듭니다. 메뉴 이름은 콘솔 버전에 따라 조금 다를 수 있습니다(예: "OAuth 동의 화면"이 "Google 인증 플랫폼(Google Auth Platform)"으로 표시될 수 있음).

1. **프로젝트 만들기**: <https://console.cloud.google.com/>에 접속해 상단의 프로젝트 선택 메뉴에서 **새 프로젝트**를 만들고 선택합니다.
2. **OAuth 동의 화면 설정**: **API 및 서비스 → OAuth 동의 화면**(또는 **Google 인증 플랫폼 → 시작하기**)으로 이동합니다.
   - 앱 이름과 사용자 지원 이메일을 입력합니다.
   - 대상(User type)은 **외부(External)** 를 선택합니다.
   - 개발자 연락처 이메일을 입력하고 저장합니다.
   - 범위(Data access)는 기본 범위인 `openid`, `email`, `profile`만 사용합니다. 다른 범위는 추가하지 않습니다.
3. **테스트 사용자 추가**: 앱이 "테스트" 상태인 동안에는 등록된 계정만 로그인할 수 있습니다. **테스트 사용자(Audience → Test users)** 에서 **사용자 추가**를 눌러 본인 Google 계정(그리고 함께 쓸 사람의 계정)을 추가합니다.
4. **OAuth 클라이언트 ID 만들기**: **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**(또는 **Google 인증 플랫폼 → 클라이언트 → 클라이언트 만들기**)를 선택합니다.
   - 애플리케이션 유형: **웹 애플리케이션(Web application)**
   - 승인된 JavaScript 원본: `http://localhost:5173`
   - 승인된 리디렉션 URI: `http://localhost:5173/api/auth/callback`
5. **ID와 보안 비밀 복사**: 생성된 **클라이언트 ID**와 **클라이언트 보안 비밀번호(Client secret)** 를 복사해 둡니다. 다음 단계의 `backend/.env`에 넣습니다.

콜백은 Vite 개발 서버의 동일 출처 `/api` 프록시를 통해 FastAPI로 전달되므로, 리디렉션 URI는 백엔드 포트(8000)가 아닌 `localhost:5173`이어야 합니다.

## 2. 백엔드 설치와 설정

저장소 루트에서 실행합니다.

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
cp .env.example .env
```

> **이미 설치한 적이 있다면**: Anki 덱 가져오기 기능 때문에 백엔드 의존성 두 개(`zstandard`: 최신 Anki 덱 압축 해제, `python-multipart`: 파일 업로드 처리)가 추가되었습니다. `backend/`에서 가상 환경을 활성화한 뒤 `python -m pip install -e ".[dev]"`를 한 번 더 실행하세요. 새 데이터베이스 테이블은 없으므로 마이그레이션은 다시 하지 않아도 됩니다.

`backend/.env`를 열어 아래 값을 설정합니다.

```dotenv
DB_URL=sqlite:///./jvt.db
GOOGLE_OAUTH_CLIENT_ID=복사한-클라이언트-ID.apps.googleusercontent.com
GOOGLE_OAUTH_CLIENT_SECRET=복사한-클라이언트-보안-비밀번호
OAUTH_REDIRECT_URI=http://localhost:5173/api/auth/callback
SESSION_SECRET=생성한-긴-임의-문자열
TOKEN_ENCRYPTION_KEY=생성한-Fernet-키
GEMINI_MODEL=gemini-flash-lite-latest
```

- `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`: 1단계에서 복사한 값입니다.
- `OAUTH_REDIRECT_URI`: Google Cloud Console에 등록한 리디렉션 URI와 정확히 같아야 합니다.
- `SESSION_SECRET`: 앱 세션에 서명하는 긴 임의 문자열입니다. 생성 명령:

  ```bash
  python -c "import secrets; print(secrets.token_urlsafe(48))"
  ```

- `TOKEN_ENCRYPTION_KEY`: 로그인 시작 쿠키와 사용자별 Gemini 키를 암호화하는 Fernet 키입니다. 생성 명령:

  ```bash
  python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
  ```

  이 값을 바꾸면 이미 저장된 Gemini 키를 복호화할 수 없으므로, 사용자가 키를 다시 연결해야 합니다.
- `GEMINI_MODEL`: 예문 생성에 쓸 Gemini 모델입니다. 기본값 `gemini-flash-lite-latest`를 그대로 써도 됩니다.

Gemini API 키는 `.env`에 넣지 않습니다. 각 사용자가 앱 화면에서 직접 연결합니다.


>
> ```bash
> mv jvt.db jvt.db.bak
> alembic upgrade head
> ```

## 4. 실행 (터미널 두 개)

**터미널 1 — 백엔드** (`backend/`, 가상 환경 활성화 상태):

```bash
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

- API: <http://localhost:8000>
- API 문서: <http://localhost:8000/docs>
- 상태 확인: <http://localhost:8000/health>

**터미널 2 — 프론트엔드** (저장소 루트에서):

```bash
cd frontend
npm install
npm run dev
```

브라우저에서 <http://localhost:5173>을 엽니다. 개발 서버는 `/api` 요청을 `http://localhost:8000`으로 전달합니다. Google 로그인 리디렉션이 올바른 주소로 돌아오도록 반드시 `localhost:5173`으로 접속하세요(`127.0.0.1:5173`은 등록된 주소와 달라 실패합니다).

## 5. 사용자가 Gemini API 키 받는 방법

처음 로그인하면 앱이 키 연결 안내 화면을 자동으로 보여 줍니다. 상단의 **鍵 Gemini 키** 버튼으로 언제든 다시 열 수 있습니다. 순서는 다음과 같습니다(약 2분).

1. **Google AI Studio 열기**: 안내 화면의 버튼을 누르거나 <https://aistudio.google.com/apikey>를 새 탭에서 엽니다.
2. **Google 계정으로 로그인**: 평소 쓰는 Google 계정으로 로그인합니다. 페이지가 영어로 보여도 괜찮습니다.
3. **API 키 만들기**: **Create API key** 버튼을 누르고, 프로젝트를 고르라고 하면 기존 Google Cloud 프로젝트를 선택하거나 **Create project**로 새로 만듭니다.
4. **키 복사하기**: 만들어진 키 옆의 **Copy**를 눌러 복사합니다. 키는 `AIza`로 시작하는 39자 문자열입니다.
5. **붙여넣고 연결 확인**: 앱의 입력칸에 붙여넣고 **연결 확인**을 누릅니다. 연결되면 "연결됨 ····abcd"처럼 마지막 4자리가 표시됩니다.

알아 둘 점:

- 키 만들기는 무료이며 결제 카드가 필요 없습니다.
- 무료 등급은 사용량 제한(분당·일일 요청 수)이 있습니다. 한도에 도달하면 앱이 잠시 기다렸다가 다시 시도하라고 안내합니다.
- Gemini API 약관에 따라 만 18세 이상만 사용할 수 있습니다.
- 유럽경제지역(EEA)·스위스·영국 거주자는 결제가 연결된 유료 키를 사용해야 합니다.
- 키는 비밀번호처럼 다루세요. 다른 사람과 공유하지 마세요. 앱에서 언제든 다른 키로 바꾸거나 삭제할 수 있습니다.

## 6. Anki 덱 가져오기

Anki에서 쓰던 덱을 파일로 내보낸 뒤 이 앱에 올리면, 단어·읽기·뜻을 한 번에 단어장에 넣을 수 있습니다. 로그인만 하면 되고 Gemini 키는 없어도 됩니다.

### Anki에서 덱 내보내기

컴퓨터용 Anki 데스크톱 앱에서 합니다.

1. Anki를 열고 가져올 덱을 선택합니다.
2. 메뉴에서 **파일(File) → 내보내기(Export…)** 를 누릅니다.
3. 형식(Export format)에서 **Anki Deck Package (\*.apkg)** 를 고릅니다. **Notes in Plain Text (\*.txt)** 를 골라도 됩니다.
4. 내보낼 덱이 맞는지 확인하고 **내보내기(Export…)** 버튼을 눌러 파일을 저장합니다.

- 스케줄 정보(복습 기록)나 미디어(소리·그림) 포함 옵션은 꺼도 됩니다. 이 앱은 어차피 가져오지 않습니다.
- Anki 메뉴 이름은 언어 설정에 따라 다르게 보일 수 있어서 영어 이름을 함께 적었습니다.

### 올릴 수 있는 파일

- `.apkg`, `.txt`, `.tsv` 파일만 올릴 수 있습니다. 확장자의 대소문자는 상관없습니다.
- 파일 크기는 **최대 50 MB(52,428,800바이트)** 입니다. 더 크면 덱을 나눠서 내보내 주세요.
- **컬렉션 전체 패키지(`.colpkg`)는 지원하지 않습니다.** 덱 하나씩 `.apkg` 또는 `.txt`로 내보내 주세요.
- 텍스트 파일은 Anki가 만든 그대로의 UTF-8, 탭 구분 형식이어야 합니다. 엑셀 등에서 쉼표로 구분된 CSV 형식으로 다시 저장한 파일은 지원하지 않습니다.
- 한 번에 파일 하나만 올릴 수 있습니다.

### 앱에 올리기

1. 상단 메뉴에서 **단어 추가**를 누릅니다.
2. 오른쪽 카드 위쪽의 탭에서 **Anki 덱 가져오기**를 고릅니다. (**직접 입력** 탭은 단어를 하나씩 입력하는 화면입니다.)
3. 파일을 점선 상자에 끌어다 놓거나 **파일 선택** 버튼으로 고릅니다.
4. 진행 막대가 100%가 되면 "덱을 읽는 중…"이 표시되고, 잠시 뒤 미리보기 화면이 나옵니다. 올리는 도중에는 **업로드 취소**로 멈출 수 있습니다.

상자 아래의 **Anki에서 내보내는 방법**을 누르면 위의 내보내기 순서를 앱 안에서도 볼 수 있습니다.

### 미리보기에서 필드 고르기

미리보기 화면에는 파일 이름, 노트 개수("노트 N개"), 처음 5개 노트가 표로 나옵니다. **이 단계에서는 단어장에 아무것도 추가되지 않습니다.**

- **노트 유형** (`.apkg`만): 덱에 노트 유형이 여러 개 있으면 "이름 (N개)" 목록에서 고릅니다. 처음에는 노트가 가장 많은 유형이 선택되어 있고, 선택한 유형의 노트만 가져옵니다. 유형을 바꾸면 필드 목록과 표가 바뀝니다.
- **단어 (필수)**, **읽기 (선택)**, **뜻 (필수)**: 각 칸에 어떤 Anki 필드를 쓸지 고릅니다. 읽기 필드가 따로 없으면 읽기에서 **없음**을 고르면 됩니다.
- 앱이 필드 이름을 보고 먼저 골라 둡니다. 예를 들어 `Front`·`Word`·`Expression`·`単語`·`단어`는 단어로, `Reading`·`Kana`·`Furigana`·`読み`·`읽기`는 읽기로, `Back`·`Meaning`·`Definition`·`意味`·`뜻`은 뜻으로 잡습니다. 맞는 이름이 없으면 첫째 필드를 단어, 둘째를 읽기, 셋째를 뜻으로 잡습니다(필드가 두 개뿐이면 첫째는 단어, 둘째는 뜻, 읽기는 없음).
- 텍스트 파일에 열 이름이 없으면 필드는 "열 1", "열 2"처럼 표시됩니다.
- 표의 머리글에 붙은 **단어 / 읽기 / 뜻** 표시로 지금 고른 필드를 확인할 수 있습니다. 표에는 HTML 태그와 `[sound:…]` 같은 소리 태그를 지운 값이 보이며, 실제로 가져올 때도 같은 방식으로 정리됩니다.
- 단어나 뜻을 고르지 않았거나 같은 필드를 두 칸에 골랐다면 해당 칸 아래에 빨간 안내가 나오고, 고칠 때까지 가져오기가 진행되지 않습니다.
- 다 골랐으면 **N개 노트 가져오기**를 누릅니다. 그만두려면 **취소**를 누르세요. 올린 파일은 바로 지워집니다.
- 미리보기는 **30분 동안만** 유지됩니다. 시간이 지났거나 이미 가져오기·취소를 했다면 "미리보기가 만료되었어요" 안내가 나오니 파일을 다시 올려 주세요.

### 후리가나 표기와 읽기 정하는 규칙

Anki에서 흔히 쓰는 `한자[읽기]` 형태의 후리가나 표기를 알아봅니다.

- **단어**에서는 대괄호 부분을 빼고 저장합니다. 읽기 필드를 골랐는지와 상관없이 항상 그렇습니다.
- 후리가나 앞에 붙은 띄어쓰기 한 칸은 구분용으로 보고 지웁니다.

| Anki 단어 필드 | 저장되는 단어 | 후리가나에서 얻는 읽기 |
| --- | --- | --- |
| `漢字[かんじ]` | 漢字 | かんじ |
| `食[た]べる` | 食べる | たべる |
| `私[わたし]は 日本[にほん]` | 私は日本 | わたしはにほん |

**읽기**는 아래 순서로 정합니다. 앞의 것이 있으면 그것을 씁니다.

1. 읽기 필드를 골랐고 그 값이 비어 있지 않으면, 그 값
2. 그렇지 않고 단어 필드에 후리가나 표기가 있으면, 후리가나에서 얻은 읽기 (위 표의 오른쪽 열)
3. 둘 다 없으면, 단어 그대로 (예: `ねこ` → 읽기도 ねこ)

### 가져오기 결과와 건너뛰는 노트

가져오기가 끝나면 "단어 N개를 추가했어요"와 함께 건너뛴 노트 수가 이유별로 나옵니다. 아래 순서로 처음 해당하는 이유 하나로 셉니다.

| 표시 | 언제 건너뛰나요 |
| --- | --- |
| **빈 항목** | 정리한 뒤의 단어나 뜻이 비어 있을 때 (읽기는 비어 있어도 위 규칙으로 채워지므로 괜찮습니다) |
| **길이 초과** | 단어가 50자, 읽기가 100자, 뜻이 500자를 넘을 때. 잘라서 넣지 않고 노트 전체를 건너뜁니다 |
| **중복** | 단어가 단어장에 이미 있는 단어와 똑같거나, 같은 파일 앞쪽에서 이미 가져온 단어와 똑같을 때. 기존 단어는 바뀌지 않습니다 |

- 건너뛴 노트는 파일 순서대로 처음 20개까지 단어와 이유가 함께 표시됩니다. 단어가 비어 있으면 "(빈 단어)"로 보입니다. 20개를 넘으면 "건너뛴 노트 중 처음 20개만 보여요"가 표시됩니다.
- 결과 화면에서 **다른 덱 가져오기**로 다음 파일을 올리거나 **복습하러 가기**로 바로 복습할 수 있습니다.

### 알아 둘 점

- **단어·읽기·뜻만 가져옵니다.** Anki의 스케줄 정보(복습 기록, 간격, 기한)와 미디어 파일(소리·그림)은 가져오지 않습니다. 가져온 단어는 모두 새 단어로 시작하고 **오늘 복습 목록에 바로** 나타납니다.
- **가져오기가 중간에 실패하면 단어를 하나도 추가하지 않습니다.** 일부만 들어가는 일은 없고 단어장은 가져오기 전과 같습니다. "가져오기에 실패해 단어를 하나도 추가하지 않았어요." 안내가 나오면 잠시 후 파일을 다시 올려 주세요.
- 같은 계정으로 가져오기가 이미 진행 중이면 "다른 가져오기가 진행 중이에요" 안내가 나옵니다. 미리보기는 그대로 남아 있으니 끝난 뒤 다시 누르면 됩니다.
- 올린 파일은 서버의 임시 폴더에서만 다루고, 가져오기가 끝나거나 실패하거나 취소되거나 30분이 지나면 지웁니다. 파일 속 데이터는 읽기만 하고, 그 안에 든 프로그램이나 스크립트는 실행하지 않습니다.
- 가져온 단어는 파일을 올린 사람의 단어장에만 들어갑니다.

## 테스트와 빌드

### 백엔드

```bash
cd backend
source .venv/bin/activate
pytest
```

Google 로그인과 Gemini 호출은 테스트에서 모두 가짜 전송 계층(`httpx.MockTransport`)으로 대체되므로 실제 키나 네트워크가 필요 없습니다. 일부만 실행하려면:

```bash
pytest tests/integration/test_auth_routes.py
pytest tests/integration/test_gemini_key_routes.py
```

### 프론트엔드

```bash
cd frontend
npm test -- --run
npx tsc -b
npm run build
```

프로덕션 빌드 결과는 `frontend/dist/`에 생성됩니다. 로컬에서 확인하려면 `npm run preview`를 실행합니다.
